# Observable · Roften

Самостоятельный приёмник и просмотрщик отчётов Observable 5.4.4 для NeoForge 1.21.1.
Целевой адрес: **https://observable.roften.ru**. Сервис пока не установлен на VPS.

## Что готово

- Совместимость со штатной отправкой мода: POST gzip JSON → URL обычным текстом.
- Ссылки на отчёты, поиск, фильтры по измерению и виду объекта, сортировка.
- Время вызова и нагрузка за тик замера, координаты, команда телепортации.
- Дерево сэмплов сервера и выбранного объекта, исходная диагностика.
- Открытие локальных JSON и JSON.GZ без отправки на сервер, скачивание исходника.
- Срок хранения 30 дней, автоматическое удаление, лимиты размера и частоты загрузок.

## Мод менять не нужно

В приложенном `[Kotlin + Architectury][RU]observable-5.4.4.jar` есть настройка
`uploadURL`. Она читается в `Profiler.uploadProfile()` и по умолчанию равна
`https://observable.tas.sh/v1/add`. Настройки находятся в серверном
`config/observable.json`. Команда `/observable set uploadURL "..."` изменяет
значение в памяти и сохраняет его в файл, поэтому перезапуск Minecraft не нужен.
Кавычки вокруг URL обязательны: аргумент команды — Brigadier string.

**Сначала разверните и проверьте сервис, затем переключайте мод.**

## Установка на Ubuntu с Docker Compose и Nginx

### 1. DNS

В панели управления доменом roften.ru добавьте запись:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | observable | 199.189.254.39 |

Не меняйте существующую запись `@` для roften.ru. Поддомен может работать
на том же VPS, где размещено радио. Новый конфиг обслуживает только
`observable.roften.ru`. Если IPv6 на VPS не настроен, запись AAAA не добавляйте.

Проверьте: `dig +short A observable.roften.ru`.

### 2. Запуск сервиса

Распакуйте каталог `observable-roften` на VPS, например в `/opt/observable-roften`.
Проверьте, что локальный порт 18085 свободен: `ss -ltnp 'sport = :18085'`.

```bash
cd /opt/observable-roften
python3 setup.py
docker compose up -d --build
curl --fail http://127.0.0.1:18085/healthz
```

`setup.py` один раз создаёт `.env` со случайным секретом и выводит команду
для Minecraft. Повторный запуск не меняет секрет. Вывод команды храните приватно.
Сервис принимает загрузки только по секретному URL. Доступ к отчётам — по
непредсказуемой ссылке; общей публичной страницы со списком отчётов нет.

### 3. Поддомен и HTTPS

Убедитесь, что другого server-блока с `server_name observable.roften.ru` нет.
Если файл назначения уже существует, сравните его вручную вместо перезаписи.

```bash
sudo cp --no-clobber nginx.conf /etc/nginx/sites-available/observable.roften.ru
sudo ln -s /etc/nginx/sites-available/observable.roften.ru /etc/nginx/sites-enabled/observable.roften.ru
sudo nginx -t
sudo systemctl reload nginx
```

Выполняйте reload только после успешного `nginx -t`. После обновления DNS и
при доступных портах 80/443 выпустите сертификат установленным Certbot:

```bash
sudo certbot --nginx -d observable.roften.ru --redirect
curl --fail https://observable.roften.ru/healthz
```

Если Nginx или Certbot не установлены, сначала установите пакеты `nginx`,
`certbot`, `python3-certbot-nginx` стандартным способом для вашей ОС.
Не устанавливайте второй Nginx поверх уже работающего контейнерного прокси:
в таком случае адаптируйте существующий прокси к локальному порту 18085.

### 4. Переключение Observable

Снова запустите `python3 setup.py`, скопируйте выведенную команду и выполните её
в игре от администратора. Вид команды:

```text
/observable set uploadURL "https://observable.roften.ru/v1/add/ВАШ_СЕКРЕТ"
```

Запустите короткий замер через GUI Observable и откройте полученную ссылку.
Проверьте, что на странице совпадают число тиков, координаты и несколько
значений с результатами в игре. Это необходимая заключительная проверка на
реальном сервере: здесь использовались тестовые данные по схеме установленного JAR.

Для возврата к исходному адресу:

```text
/observable set uploadURL "https://observable.tas.sh/v1/add"
```

Можно изменить только поле `uploadURL` в существующем `config/observable.json`
при остановленном Minecraft и запустить сервер. Не заменяйте весь конфиг:
в нём находятся права доступа и настройки замера.

## Расчёты и ограничения

Поле `rate` хранит наносекунды на вызов объекта. Просмотрщик показывает
`rate / 1 000 000` мс. Нагрузка на один тик замера равна
`rate × entry.ticks / data.ticks / 1 000 000` мс. Сводка складывает учтённые
блоки и сущности; она **не равна полному MSPT сервера** и может включать
пересекающиеся измерения. В стеке показываются сэмплы, а не миллисекунды.

Сервис не меняет алгоритм профилирования и его нагрузку. Он принимает готовый
результат. Этот комплект не добавляет локальное резервное сохранение в сам мод:
если отправка не удалась, используйте штатный экспорт результата на клиенте,
пока он доступен. Экспортированный JSON можно открыть на главной странице.

Лимиты: до 8 МиБ передаваемого тела, до 32 МиБ после распаковки; значения
заданы в `app.py`, лимит Nginx — в `nginx.conf`. Контейнер ограничен 512 МиБ ОЗУ
и одним CPU. Для очень больших замеров может потребоваться настройка лимитов.
Стек отображается по веткам с ограничением глубины и числа узлов; исходник полный.

Диагностика штатного мода может включать аргументы JVM и другие сведения
о сервере. Перед передачей ссылки посторонним проверьте раздел «Диагностика».
Публичная ссылка позволяет прочитать весь отчёт до удаления или истечения срока.

Токен загрузки нельзя размещать в публичном репозитории или сообщениях.
Uvicorn access log отключён, а Nginx не пишет access log для адреса загрузки.
Minecraft сохраняет uploadURL в своём конфиге; доступ к конфигам ограничьте.

## Обслуживание

```bash
docker compose ps
docker compose logs --tail=100 observable
```

Данные хранятся в Docker volume `reports`. Обычные `up`, `down` и пересборка
сохраняют их. Команда `docker compose down -v` удалит отчёты — не используйте
её для обновления. Для резервных копий сохраняйте volume и `.env`.

## Локальная проверка кода

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt httpx==0.28.1
cd /path/to/observable-roften
.venv/bin/python -m unittest discover -s tests -v
```

Docker, Nginx, DNS, сертификат и реальный игровой замер проверяются после
установки на выбранном VPS. Этот сервис написан отдельно; код Observable
не включён и исходный JAR не изменён.
